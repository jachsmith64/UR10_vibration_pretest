## 本轮版本说明（V1.3）

### 一、为什么要换掉 V1.2 的慢偏移拟合（§二）

被测对象的 TCP Y 位移可以写成

```
e_raw(t) = b(t) + e_vib(t)
```

`b(t)` 是准静态/方向性慢偏移（正向稳态偏 +24 µm、反向稳态偏 −19 µm 量级），
`e_vib(t)` 才是要抗的净振动。

V1.1 直接对 `e_raw` 重建，于是重建出来的 `Fd` 有一大半力气花在复现那个慢偏移上，
A0 的响应整体坐在一边，SFC 的作用被掩盖。

V1.2 的做法是先扣掉 `b(t)` 再重建。方向对，但**拟合的自由度太高**：
每条曲线有几十个分箱 + 一个 LOWESS 平滑带宽。出问题时无法用肉眼判断
「这是真实的慢变化，还是拟合把振动吸进去了」。

V1.3 的判断是：**慢偏移就该是慢的、稳的、可以被几个数说清楚的。**
自由度从「几十个分箱 + 一个带宽」压到 **4 个数**，形状还是固定的余弦，
没有任何可调自由度。目的是让每一条判断都能被单独核对。

### 二、`b(t)` 的正式构造（§三 / §四 / §五）

```
段名            区间               b(t)
pre_motion      [0, p1]            b_pre      （常值）
start           [p1+1, iA-1]       余弦 b_pre → b_out
fwd_steady      [iA, iB]           b_out      （常值）
turn            [iB+1, iC-1]       余弦 b_out → b_ret
ret_steady      [iC, iD]           b_ret      （常值）
stop            [iD+1, q0-1]       余弦 b_ret → b_post
post_stop       [q0, n-1]          b_post     （常值）
```

七个区间无缝覆盖 `[0, n-1]`，无重叠、无空洞（`drift._assemble` 断言保证）。
**只有 start / turn / stop 三段允许变化，其余四段严格为常值**
（`drift_baseline_summary.json` 的 `per_segment` 里逐段核对了 ptp = 0）。

四个稳定值全部**现算**，代码里一个都没有写死：

| 值 | 取值规则 | 窗口 |
|---|---|---|
| `b_pre` | `pre_motion` 整段中位数 | n = 1285 |
| `b_out` | `X_outbound` 稳态窗中位数（`nominal_along_mm` ≈ 3.20–11.00 mm） | n = 1536 |
| `b_ret` | `X_return` 稳态窗中位数（`nominal_along_mm` ≈ 10.67–0.17 mm） | n = 2050 |
| `b_post` | `post_stop` 整段中位数 | n = 1142 |

三段过渡只用余弦桥接，形状固定：

```
w = 0.5·(1 − cos(πs)),   s ∈ [0,1]
b = (1 − w)·b_start + w·b_end
```

过渡**只由两端常值和固定余弦决定，不跟随原始数据里的瞬态尖峰**，因此绝不会
长出锯齿状基线。它是否把真实瞬态吃掉了，由两把尺子独立核对：

- **解析斜率上界。** 余弦 `w = 0.5(1−cos πs)` 在 n 个点上的一阶差分有精确上界
  `max|Δw| = sin(πh/2)`，`h = 1/(n−1)`（在段中点取到），故
  `max|Δb| = |Δb_段|·sin(π/(2(n−1)))`。这是余弦的解析性质，不是拍的容差；
  拼接错位、端点写错、中途插阶跃，比值都会立刻 > 1。
- **ptp 硬下界。** `ptp(e_raw − b) ≥ ptp(e_raw) − ptp(b)`，而 b 在该段单调，
  `ptp(b) = |Δb|`。即「b 至多吃掉与自身变化量相等的峰谷」，恒成立。

### 三、§八 的机器可判验收（26 项全部通过）

```
b_pre = -0.044 µm   b_out = +24.153 µm   b_ret = -18.964 µm   b_post = +4.094 µm
b(t) 范围 -18.96 ~ 24.15 µm

过渡 start  n= 641   -0.044 → +24.153 µm  单调=True  max|Δb|=5.939e-02 µm
过渡 turn   n=1062  +24.153 → -18.964 µm  单调=True  max|Δb|=6.383e-02 µm
过渡 stop   n=  40  -18.964 →  +4.094 µm  单调=True  max|Δb|=9.284e-01 µm

稳态 fwd_steady  median +24.153 → +0.000 | mean +23.440 →  -0.713 | rms 28.266 → 15.812 µm (+44.1%)
稳态 ret_steady  median -18.964 → -0.000 | mean -19.715 →  -0.752 | rms 25.856 → 16.745 µm (+35.2%)

整体：e_raw rms 35.526 → e_vib rms 27.996 µm（−21.2%）
振动带（2.5–45 Hz）保留：fwd 100.0% / ret 100.0%
```

**一条必须说清楚的注记（已写进 `drift_baseline_summary.json` 的 `notes`）：**
稳态段 `e_vib` 的中位数恰好是 0，这是**构造必然**——`b_out`/`b_ret` 就是取该窗
中位数得到的。所以中位数为 0 **不能**当作「去偏移效果好」的证据，
请看 mean / RMS 与过渡段的 ptp。

**第二条注记：`post_stop` 段不平稳。** 整段中位数 +4.094 µm，但尾 0.5 s 中位数
为 +10.489 µm，段内中位数单调爬升 −6.98 → +9.17 µm。本模块按 §三.4 取整段
中位数，因此 `post_stop` 段会残留约 ±10 µm 的慢沉降。这段慢变化是**真实的、
未被建模的**，如实保留、没有静默平滑掉。

**窗口敏感性：** 边界内缩 ±100 点时，`b_out` 只在 2.76 µm 内变动、`b_ret` 只在
1.22 µm 内变动——说明这四个数不是靠边界位置凑出来的。

### 四、扰动重建（§六 / §九）

`e_vib(t)` 是**唯一**的重建口径。全部正式重建一律用 `e_vib`，绝不使用原始 `e_raw`。

```
Plant 标定  G(f)：TCP Y 力 → TCP Y 位移，3000 bins（0.017–50 Hz），DC 静柔度 94.89 µm/N
反演        Fd = irfft( rfft(e_vib)/G · cos_taper )，带限 ≤30 Hz（45 Hz 渐减到 0）
残差迭代    lr = 0.7，残差/目标 ≤ 20% 即停
```

本轮结果：迭代 2 次后

```
e_sim rms 16.65 µm  vs  目标 18.12 µm
corr 0.9932         残差 rms 2.72 µm（目标的 15.0%）  ← 已达门槛，提前收敛
Fd rms 0.944 N，峰值 4.642 N，sha256 58858d990d4f…
```

TCP 施力点校验：`max|q_applyFT − J_tcp^T·F| = 0.000e+00`（参考量级 6.910e-01），
即 `mj_applyFT` 折算出的广义力与 `J_tcp^T·[0,F,0]` 数值完全一致，Fd 真正作用在 TCP 上。

**Fd 与 SFC 解耦仍然成立：** SFC 绝不读取 Fd；Fd 绝不根据 `e_sim` 在线重算；
正式运行只读冻结文件，SHA-256 在加载时校验。

## 六、机制验证测试（§十一）

### 测试 A：扰动幅值缩放 `Fd_test = s·Fd`

只跑 Alinear 与 ASFC_strong（s = 1.0 直接复用正式组，不重跑）。

| s | Alinear RMS (µm) | ASFC_strong RMS (µm) | ASFC 额外改善 |
|---|---|---|---|
| 0.5 | 6.541 | 5.455 | **+16.61%** |
| 1.0 | 12.335 | 9.651 | **+21.75%** |
| 1.5 | 18.311 | 13.776 | **+24.76%** |

> **结论：ASFC 相对 Alinear 的额外改善随扰动幅值单调增大**（16.61% → 21.75% → 24.76%）。
> 这正是剪切增稠该有的样子：扰动越大、速度越高，`μ|v|^(n−1)v` 项占比越大。

### 测试 B：慢偏移估计误差 `b̂ = b + Δb` 的鲁棒性

`Δb = −10 / −5 / +5 / +10 µm`，每个 Δb 都**重新走完整重建**（用同一份 Plant 标定），
再跑 ASFC_strong。只与「正确基线的 ASFC_strong」比。

| Δb (µm) | ASFC_strong RMS (µm) | RMS 变化 | 峰值 (µm) | 峰值变化 |
|---|---|---|---|---|
| 0（正确基线） | 9.651 | — | 59.515 | — |
| −10 | 10.711 | +10.98% | 65.572 | +10.18% |
| −5 | 9.650 | **−0.02%** | 62.166 | +4.45% |
| +5 | 10.716 | +11.03% | 62.562 | +5.12% |
| +10 | 12.576 | **+30.30%** | 65.609 | +10.24% |

> **结论：几 µm 级偏差基本不损伤主效果**（Δb = −5 µm 时 RMS 变化 −0.02%，即完全无感），
> **±10 µm 时退化开始明显**（RMS 最多 +30%），但仍保持「比 Alinear 好」——
> 因为 10.7–12.6 µm 仍显著低于 Alinear 的 12.335 µm（Δb = +10 时略差于此）。
> 注意 ±10 µm 已经和 `b_post` 段的真实慢沉降（±10 µm）同量级，属于偏保守的加严测试。

### 测试 C：逐事件比较「峰值 / 恢复 / 反向过冲」（纯离线）

由 A0 定位 30 个代表峰，逐对比较 Alinear 与 ASFC_strong：

| 指标 | 结果 |
|---|---|
| 峰值 | **ASFC 更低**：更低 30 / 持平 0 / 更高 0，中位变化 **−7.295 µm** |
| 回正时间（降到峰值的 50%） | **ASFC 略慢**：更慢 25 / 更快 3，中位变化 **+0.0050 s** |
| 反向过冲 | **ASFC 更小**：更小 28 / 更大 0，中位变化 **−9.838 µm** |

> **结论：不存在实质性的「阻碍回正」。** 回正时间的中位差只有 5 ms（在 1 kHz 物理步长
> 上相当于 5 个控制拍，远小于峰值的持续时间），而代价换来的是峰值低 7.3 µm、
> 反向过冲小 9.8 µm。也就是说，ASFC 的「回正略慢」是**峰值更低导致的相对时间变长**，
> 不是额外注能造成的迟滞——这与 §五 里 `P_shear > 0` 比例为 0（全程耗散）互相印证。
> 更准确的说法：**ASFC 降低了反向过冲、让整体波动更平稳，而不是妨碍回正。**

### 测试 D：分相统计（稳态段 vs 突变段）

| 相位 | A0 RMS | Alinear RMS | ASFC_strong RMS | ASFC 相对 Alinear | 峰值改善 |
|---|---|---|---|---|---|
| start（启动突变） | 35.597 | 24.276 | 21.221 | +12.58% | +16.74% |
| **fwd_steady（正向稳态）** | 14.672 | 10.955 | 7.816 | **+28.65%** | +3.23% |
| turn（远端换向） | 41.333 | 32.156 | 28.138 | +12.50% | +15.66% |
| **ret_steady（反向稳态）** | 15.172 | 11.318 | 8.891 | **+21.45%** | +23.87% |
| stop（停止突变） | 8.721 | 6.112 | 4.905 | +19.75% | +46.96% |

> **结论与直觉相反，但数据是这样：SFC 的相对收益在稳态段更大，不是只在突变段有效。**
> 突变段平均改善 +14.94%，稳态段平均改善 +25.05%。
> 原因也说得通：剪切增稠对**速度幅值**敏感，而稳态段的持续振动给了它稳定的
> 速度分布去发挥作用；突变段主体是大幅值的低频摆动，`B0·v` 线性项已经吃掉了大部分，
> 留给非线性项的边际空间反而小。
> 需要补充的是，**绝对量**上突变段仍是主战场：start/turn 两段的 RMS 是稳态段的 2–3 倍
> （35.6 / 41.3 vs 14.7），所以「SFC 的价值主要体现在把大振动压下来」这个说法
> 在绝对量上成立，在相对百分比上不成立。

## 九、已知的限制与诚实的边界

1. **慢偏移在转向段的归属本质上是不确定的。** 换向时速度反向，`b` 既不是 `x` 的
   纯函数，也不是 `t` 的纯函数。V1.3 用「余弦过渡」把它参数化了，
   这是**一个建模选择**，不是从数据里唯一确定出来的。
2. **`post_stop` 段的慢沉降没有被建模**（见 §三 第二条注记），会以 ±10 µm 的
   慢变化残留在 `e_vib` 里。这是**有意保留**的，因为静默平滑掉它就等于
   把一段真实信号藏起来。
3. **本轮的 `e_raw` 是理想 oracle 口径**：允许离线使用全段数据与未来帧，
   **不是** 132 Hz 在线估计，也**不是**真实部署。真实部署还要面对在线估计误差、
   延迟、视觉丢帧等问题，本轮一律没有涉及（§十六 明确禁止）。
4. **Fd 是等效扰动力**，不是真实机械臂实际受到的物理外力；
   Plant 是线性时不变的频响近似，`Fd` 幅值受 `plant_frf` 的线性假设约束。
5. **测试 B 的 4 次重建只交付 `fd_meta.json`**，各自的 `fd_frozen.csv`（各约 1 MB）
   未收进 DATA 包；需要复算时按 `fd_meta.json` 里的参数重跑 `--reconstruct` 即可。
6. **DATA 包里唯一一个中文文件名 `data/P05R01/D1_时序.csv`：**
   它按 ZIP 规范以 UTF-8 编码存储并置了 UTF-8 标志位（APPNOTE 6.3.0 §4.4.4），
   与工作树里的文件名字节**逐字节相同**（`_verifyzip.py` 会实际核对这两点）。
   但 **Git Bash 自带的 Info-ZIP `unzip` 会忽略该标志位**、按 cp1252 解码，
   把文件名解成 `D1_µùÂզÅ.csv`（**文件内容完好，只是名字显示错**）。
   复核时请改用 7-Zip / Windows 资源管理器 / bsdtar / Python `zipfile` /
   macOS 归档实用工具，或给 unzip 加 `-O UTF-8`。
